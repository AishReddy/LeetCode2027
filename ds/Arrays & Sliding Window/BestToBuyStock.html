Easy Array Sliding Window Greedy LeetCode #121

Best Time to Buy &
Sell Stock / Java

Find the maximum profit achievable by buying on one day and selling on a later day. You may only complete one transaction.

Problem Statement

Given an array prices where prices[i] is the stock price on day i, return the maximum profit you can achieve. You must buy before you sell. If no profit is possible, return 0.

Example 1
Input: [7, 1, 5, 3, 6, 4]
Output: 5
Buy on day 2 (price=1), sell on day 5 (price=6). Profit = 6−1 = 5
Example 2
Input: [7, 6, 4, 3, 1]
Output: 0
Prices only decrease — no profitable transaction possible.
Approaches

Brute Force

Try every pair (buy day, sell day) where buy < sell, compute profit, keep the max. Simple but slow — checks n×(n−1)/2 pairs.

Time O(n²) Space O(1)

One Pass / Greedy

Track the minimum price seen so far. For every new price, compute profit against that minimum and update the max profit. Single scan, no extra memory.

Time O(n) Space O(1)
Solution Code
MaxProfit.java 
class Solution {

    /**
     * Returns the maximum profit from a single buy-sell transaction.
     * Time  : O(n)  — one pass through the prices array
     * Space : O(1)  — only two variables regardless of input size
     */
    public int maxProfit(int[] prices) {
        int minPrice  = Integer.MAX_VALUE;
        int maxProfit = 0;

        for (int price : prices) {
            if (price < minPrice) {
                minPrice = price;           // found a cheaper buy day
            } else if (price - minPrice > maxProfit) {
                maxProfit = price - minPrice; // better profit found
            }
        }

        return maxProfit;
    }
}
How It Works
1

Initialise two trackers

minPrice starts at Integer.MAX_VALUE so any real price beats it on the first iteration. maxProfit starts at 0 — the minimum answer (no trade).

2

Scan prices left to right

For each price, we ask two questions: is this cheaper than any price seen before? If yes, update minPrice. Otherwise, would selling today beat our best profit?

3

Update minimum buy price

If price < minPrice, we found a better day to have bought. We shift our imaginary buy day forward. We cannot sell on this day (buy < sell enforced implicitly).

4

Update maximum profit

Otherwise compute price − minPrice. If this beats maxProfit, record it. The else if guarantees we never compute profit on the same day we update minPrice.

5

Return result

After one full pass, maxProfit holds the best possible single-transaction profit. If prices only fell, it stays 0 — the correct answer when no profit is achievable.

Only minPrice and maxProfit — two integers. Memory usage is constant regardless of how large the input array is.

Edge Cases

Decreasing prices

Prices fall every day — no profitable trade exists. maxProfit stays 0, which is returned as the answer.

Input: [7, 6, 4, 3, 1] → 0

Single element

Only one price — you can't both buy and sell. The loop runs once, no profit update fires, returns 0.

Input: [5] → 0

All same price

Every day has the same price. Profit is always 0 — the else if never triggers since price − minPrice = 0.

Input: [3, 3, 3, 3] → 0

Best buy is last trough

The minimum price appears late in the array. The algorithm correctly tracks the running minimum and updates it whenever a cheaper price is found.

Input: [9, 3, 7, 1, 8] → 7

Two elements

Minimum possible input for a transaction. Result is max(0, prices[1] − prices[0]).

Input: [2, 5] → 3

Large spike at end

Profit is found on the very last day. The algorithm keeps updating maxProfit until the loop ends, capturing this correctly.

Input: [1, 2, 3, 4, 100] → 99
