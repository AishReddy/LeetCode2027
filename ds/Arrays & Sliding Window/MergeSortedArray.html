Merge Sorted Array

Three-pointer merge from the back — in-place, no extra space

easy O(m+n) time O(1) space
Problem

You are given two sorted integer arrays nums1 (size m+n, last n slots are zeros) and nums2 (size n). Merge nums2 into nums1 in-place so that nums1 becomes sorted.

nums1 = [2, 3, 4, 0, 0]   m=3
nums2 = [4, 5]   n=2
Output: [2, 3, 4, 4, 5]
⚡ Key insight: merging from the front requires shifting elements — expensive. Merging from the back fills the empty zero slots directly. The largest element always goes to the last empty slot — no shifting needed.
Why merge from the back?
✗ Front-to-back (naive)
Insert into position → must shift everything right to make room.
Each insertion = O(n) shift → total O(n²). Also risks overwriting unread values in nums1.
✓ Back-to-front (optimal)
Empty slots at the tail of nums1 are waiting to be filled. Place the largest element there first. Pointers only move backward — no shifting, no overwriting.
✓ The zero-padding in nums1 is not a bug — it's the space reserved for the merge. Back-to-front uses it perfectly.
Three-pointer approach
p1
p1 — points to the last real element of nums1, starts at index m-1. Moves left after each placement.
p2
p2 — points to the last element of nums2, starts at index n-1. Moves left after each placement.
k
k — the write cursor, starts at the very last index m+n-1. Always receives the larger of nums1[p1] vs nums2[p2]. Moves left every iteration.
✓ When p2 reaches -1, nums2 is fully merged — done. Any remaining nums1 elements are already in place. If p1 reaches -1 first, copy remaining nums2 elements to the front of nums1.

Java solution

        
class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        int p1 = m - 1;           // last real element of nums1
        int p2 = n - 1;           // last element of nums2
        int k  = m + n - 1;       // write position (last slot)

        while (p2 >= 0) {         // keep going until nums2 exhausted
            if (p1 >= 0 && nums1[p1] > nums2[p2]) {
                nums1[k--] = nums1[p1--];   // nums1 wins
            } else {
                nums1[k--] = nums2[p2--];   // nums2 wins (or p1 exhausted)
            }
        }
    }
}


        

            

                
Why loop on p2 ≥ 0?

                

                    If nums2 is exhausted (p2 < 0), the remaining nums1 elements are already in their correct positions — nothing to do. But if nums1 is exhausted first, nums2 remainders must still be copied.
                

            

            

                
Why check p1 ≥ 0 inside?

                

                    If nums1 is exhausted (p1 < 0), skip the comparison and always take from nums2. The else branch handles both "nums2 wins" AND "nums1 is empty".
                

            

            

                
Invariant

                

                    After each iteration: nums1[k+1 .. m+n-1] is finalized and sorted. The region [0..k] still contains unprocessed elements. k always moves left by exactly 1 per iteration.
                

            

        

    


    
    

        
Complexity

        

            

                
Time

                
O(m+n)

                
Each element from both arrays is placed exactly once. No inner loops, no shifting. Single backward pass.

            

            

                
Space

                
O(1)

                
Three integer pointers. All writes go directly into nums1's pre-allocated tail space.

            

        

        

            The naive approach (merge into temp array, copy back) is O(m+n) time but O(m+n) space. This back-to-front approach achieves the same time at O(1) space by exploiting the reserved zeros.
        

    


    
    

        
Edge cases

        

            

                n = 0
                nums2 is empty → p2=-1 → loop never runs → nums1 unchanged ✓
                m = 0
                nums1 has no real elements → p1=-1 → always take from nums2 until exhausted ✓
                all nums2 > nums1
                p1 exhausts first → remainder of nums2 fills the front of nums1 ✓
                all nums2 < nums1
                nums1 elements fill k..m positions first, then nums2 fills [0..n-1] ✓
