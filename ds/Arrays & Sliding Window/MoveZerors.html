Move Zeroes

Two-pointer in-place array partition

easy O(n) time O(1) space
Problem

Given an integer array nums, move all 0s to the end while maintaining the relative order of non-zero elements. Must be done in-place with minimal total operations.

Input:  [0, 1, 0, 3, 12]
Output: [1, 3, 12, 0, 0]

Input:  [0, 0, 1]
Output: [1, 0, 0]
⚡ Key insight: pointer i tracks the next zero slot; pointer j scans ahead for the next non-zero. When found, swap. The two pointers "push" non-zeroes left and zeroes right without any extra array.
Two-pointer approach
i
Write pointer (i) — always points to the current zero that needs to be filled. Only advances after a successful swap.
j
Scan pointer (j) — races ahead of i looking for a non-zero value. When it finds one, that value swaps with nums[i].
swap
Swap condition — only swap when nums[i] == 0 AND nums[j] != 0. Both i and j advance after. If nums[i] != 0, advance both together.
✓ Every element is visited at most once by j. No shifting, no extra passes. Minimal writes (only actual swaps happen — no unnecessary moves).

Java solution

        
class Solution {
    public void moveZeroes(int[] nums) {
        if (nums.length <= 1) return;

        int i = 0, j = 1;                      // i = write ptr, j = scan ptr

        while (j < nums.length) {
            if (nums[i] == 0) {
                if (nums[j] == 0) {
                    j++;                          // both zero → j skips ahead
                } else {
                    nums[i] = nums[j];            // swap: pull non-zero to i
                    nums[j] = 0;
                    i++; j++;
                }
            } else {
                i++; j++;                         // nums[i] != 0: both advance
            }
        }
    }
}


        

            

                
Why i starts at 0, j at 1?

                

                    i needs to point at a zero before j can fill it.

                    If nums[0] != 0, both advance together and i "catches up" — i never goes past j.
                

            

            

                
Why j skips when both are 0?

                

                    No useful swap. i stays locked on its zero position.

                    j must find the next non-zero before a swap is valid.
                

            

            

                
Invariant

                

                    At all times: nums[0..i-1] contains non-zero values in original order. j >= i always. When the loop ends, all non-zeroes are packed left and zeroes fill the tail.
                

            

        

    


    
    

        
Complexity

        

            

                
Time

                
O(n)

                
j visits each element exactly once. i only moves on swaps. Single pass.

            

            

                
Space

                
O(1)

                
Only two integer pointers. All operations directly on the input array.

            

        

        

            Alternate simpler approach: one pointer, copy non-zeroes forward, then fill tail with zeros — also O(n)/O(1), but does more writes. This two-pointer version minimises total operations (only real swaps).
