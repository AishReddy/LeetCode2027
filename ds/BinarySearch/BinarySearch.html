704. Binary Search

LeetCode Easy — Divide & Conquer on sorted array

easy O(log n) time
Problem

Given a sorted integer array nums and a target integer target, return the index of target if it exists, otherwise return -1. You must write an algorithm with O(log n) runtime.

⚡ Linear scan is O(n). Binary search halves the search space each iteration — O(log n). On 1 billion elements it takes only ~30 steps.
Approach — Two Pointers (left, right)
1
Initialise: left = 0, right = nums.length - 1. The search window is [left … right].
2
Compute mid: mid = left + (right - left) / 2. Using left + (right-left)/2 instead of (left+right)/2 avoids integer overflow.
3
Three-way compare:
• nums[mid] == target → return mid
• nums[mid] < target → left = mid + 1 (discard left half)
• nums[mid] > target → right = mid - 1 (discard right half)
4
Not found: If left > right the window is empty — return -1.

Complexity Analysis
Time Complexity
O(log n)
Search space halves every iteration. n=1,000,000,000 → at most 30 iterations.
Space Complexity
O(1)
Only three integer variables: left, right, mid. No extra data structures.
Why left + (right-left)/2? If left and right are both large, (left+right) can overflow a 32-bit integer. Subtracting first keeps the value in range.

Condition is left <= right, not left < right: When left == right there is still one element to check — using < would miss it.
Java Solution
class Solution {
    public int search(int[] nums, int target) {
        int left  = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;  // overflow-safe

            if      (nums[mid] == target) return mid;         // found
            else if (nums[mid] <  target) left  = mid + 1;   // go right
            else                          right = mid - 1;   // go left
        }

        return -1;  // not found
    }
}
3 things to remember
1. Condition: while (left <= right) — not <
2. Mid: left + (right - left) / 2 — overflow safe
3. Shrink: left = mid+1 or right = mid-1 — never mid
Key Insight
Every iteration eliminates half the remaining elements. The array doesn't need to be touched — you only move two pointers.
n=6 → 3 → 2 → 1 → done  (at most ⌈log₂ n⌉ iterations)
Common bugs:
• Using < instead of <= → misses single-element window
• left = mid instead of left = mid+1 → infinite loop
• (left+right)/2 → integer overflow on large arrays
