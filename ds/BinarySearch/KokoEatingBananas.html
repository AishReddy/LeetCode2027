875. Koko Eating Bananas

LeetCode Medium — Binary Search on Answer

medium O(n log m) time
Problem

Koko has piles of bananas. She can eat at most k bananas per hour. Each hour she picks one pile and eats up to k from it (a partial pile still costs a full hour). Given h hours, find the minimum k that lets her finish all piles in time.

piles = [3, 6, 7, 11], h = 8
k=4: hours = ⌈3/4⌉+⌈6/4⌉+⌈7/4⌉+⌈11/4⌉ = 1+2+2+3 = 8 ✓
Answer: 4
⚡ Key insight: the answer lies in range [1, max(piles)]. As k increases, hours needed decreases — monotone! Binary search on k.
Core Idea — Binary Search on the Answer
Instead of searching an array for a value, we binary search the answer space [1…max(piles)]. For any candidate k, we can check in O(n) whether it's feasible:
hours(k) = Σ ⌈pile / k⌉   ≤ h ?
If feasible → try smaller k (go left). If not → need bigger k (go right).
✓ The feasibility function is monotone: if k works, every k' > k also works. This is the condition needed for binary search on the answer.
Approach
1
Set search range: left = 1 (min possible k), right = max(piles) (worst case: eat biggest pile in one hour).
2
Compute mid: mid = left + (right - left) / 2. This is the candidate eating speed.
3
Check feasibility: compute total hours at speed mid using (pile + mid - 1) / mid (integer ceiling division). If total hours ≤ h → feasible.
4
Binary decision:
• Feasible → record result = mid, try smaller → right = mid - 1
• Not feasible → need faster → left = mid + 1
Walkthrough   piles = [3,6,7,11], h = 8
Search range: left=1 to right=11
iter left right mid (k) hours(mid) ≤ h=8? action
Complexity Analysis
Time Complexity
O(n log m)
n = number of piles, m = max(piles). Binary search over [1…m] = O(log m) iterations. Each check = O(n). Total = O(n log m).
Space Complexity
O(1)
Only left, right, mid, result. No extra data structures.
Ceiling division without Math.ceil: (pile + k - 1) / k gives ⌈pile/k⌉ using integer arithmetic — no floating point needed.

Why right = max(piles) not Integer.MAX_VALUE? Eating at speed = max(piles) means every pile takes exactly 1 hour = n hours total. You never need k > max(piles).
Java Solution
class Solution {
    public int minEatingSpeed(int[] piles, int h) {
        int l = 1;
        int r = 0;
        for (int pile : piles)
            r = Math.max(r, pile);       // r = max(piles)

        while (l < r) {                    // l==r when done → that's the answer
            int mid = l + (r - l) / 2;
            int count = 0;
            for (int i : piles)
                count += (i + mid - 1) / mid;  // ceiling division

            if (count <= h) {
                r = mid;           // feasible — mid could be answer, keep it
            } else {
                l = mid + 1;       // too slow — mid definitely not answer
            }
        }
        return l;                          // l == r == minimum k
    }
}
Your version ✓ cleaner
Condition: while (l < r)
Feasible: r = mid (keep mid)
Returns: l (l == r == answer)
Alternate version
Condition: while (l <= r)
Feasible: result=mid; right=mid-1
Returns: result (extra variable)
Pattern to remember
1. Range: l=1, r=max(piles)
2. Check: (i + mid - 1) / mid → ceiling without Math.ceil
3. Feasible → r = mid (mid kept — it could be the answer)
4. Not feasible → l = mid + 1 (mid discarded — too slow)
5. Return l when loop ends
Key Insight
This is binary search on the answer — not on the input array. The search space is the range of possible answers [1…max(piles)].

The pattern applies whenever:
1. Answer is an integer in a known range
2. There's a feasibility function that's monotone
3. You want the min (or max) feasible value
Same pattern used in: Capacity to Ship Packages, Split Array Largest Sum, Minimum Days to Make Bouquets.
