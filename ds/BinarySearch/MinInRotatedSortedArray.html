153. Find Minimum in Rotated Sorted Array

LeetCode Medium — Modified Binary Search

medium O(log n) time
Problem

Given a sorted array that has been rotated between 1 and n times, find the minimum element. You must write an O(log n) algorithm.

Original:  [1, 2, 3, 4, 5, 6, 7]
Rotated:  [4, 5, 6, 7, 1, 2, 3] ← min = 1 (rotation point)
⚡ Key insight: the array has two sorted halves. Compare nums[mid] with nums[right] to decide which half contains the minimum.
Approach — Binary Search on Rotation Point
1
Initialise: left = 0, right = nums.length - 1.
2
Early exit: If nums[left] <= nums[right], the current window is already sorted — the minimum is nums[left]. Return it.
3
The key decision — compare mid vs right:
• nums[mid] > nums[right] → rotation point is in the right half → left = mid + 1
• nums[mid] <= nums[right] → minimum is in the left half (including mid) → right = mid
4
When left == right, the window has converged to a single element — that is the minimum. Return nums[left].
Why compare with right, not left?
Comparing nums[mid] with nums[right] tells you which side the drop is on. If nums[mid] > nums[right], there's a descending jump somewhere to the right of mid — that's where the minimum hides. If nums[mid] <= nums[right], the right half is clean and the drop is to the left of (or at) mid.

Complexity Analysis
Time Complexity
O(log n)
Each iteration halves the search window. Same as standard binary search.
Space Complexity
O(1)
Only three variables: left, right, mid.
right = mid, not mid - 1: Unlike standard binary search, we use right = mid (not mid - 1) because mid itself could be the minimum.

No duplicates version: This solution assumes all values are unique. For arrays with duplicates (LC 154), you need an extra right-- when nums[mid] == nums[right].
Java Solution
class Solution {
    public int findMin(int[] nums) {
        int left  = 0;
        int right = nums.length - 1;

        while (left < right) {              // stop when window = 1 element
            int mid = left + (right - left) / 2;

            if (nums[mid] > nums[right]) {
                left = mid + 1;              // min is in right half
            } else {
                right = mid;                 // min is mid or left of mid
            }
        }

        return nums[left];                  // left == right == min index
    }
}
3 differences from standard binary search
1. Condition: while (left < right) — not <=
2. Compare: nums[mid] vs nums[right] — not target
3. Shrink: right = mid — not mid-1
Your Version — Explicit lowest tracking
class Solution {
    public int findMin(int[] nums) {
        int l = 0;
        int r = nums.length - 1;
        int lowest = Integer.MAX_VALUE;

        while (l <= r) {
            int mid = l + (r - l) / 2;

            if (nums[l] <= nums[mid]) {
                // left half is sorted → nums[l] is its minimum
                lowest = Math.min(lowest, nums[l]);
                l = mid + 1;
            } else {
                // right half has the drop → nums[mid] could be the minimum
                lowest = Math.min(lowest, nums[mid]);
                r = mid - 1;
            }
        }
        return lowest;
    }
}

Key Insight
A rotated sorted array always has exactly one inflection point — where a larger value is immediately followed by a smaller one. That's the minimum.
4 5 6 7 ↓ 1 2 3
left half (bigger)     min    right half (smaller)
If nums[mid] > nums[right] → the inflection is to the right of mid.
If nums[mid] <= nums[right] → the inflection is at or to the left of mid.
