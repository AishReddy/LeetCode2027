49. Group Anagrams

LeetCode Medium — Frequency Array Key + HashMap

medium O(n·k) time — no sorting!
Problem

Given an array of strings strs, group the anagrams together and return them as a list of lists. Order does not matter.

⚡ Sorting each word costs O(k log k). Instead, build an int[26] frequency count per word and encode it as a string key — O(k) per word, O(n·k) total.
✓ All anagrams produce the exact same int[26] array → same encoded key → same HashMap bucket.
Approach — int[26] Frequency Key + HashMap
1
Create HashMap map — key = encoded frequency string, value = list of words with that frequency profile.
2
For each word build int[] count = new int[26]. For every character: count[c - 'a']++. This is O(k) — no sorting needed.
3
Encode the key: append each count + a delimiter '#' to a StringBuilder. e.g. "eat" → "1#0#0#0#1#...#1#..." The '#' delimiter prevents count=12 colliding with count=1 followed by 2.
4
Add to map using computeIfAbsent, then return new ArrayList<>(map.values()).

Complexity Analysis
Time Complexity
O(n·k)
n words × O(k) per word to build int[26] + O(26) to encode key. No sorting. HashMap ops O(1) avg.
Space Complexity
O(n·k)
HashMap stores all n words. Each encoded key is O(26) = O(1). Total space dominated by the words themselves.
vs. Sorted Key O(n·k log k): Sorting each word takes O(k log k). The freq array approach replaces that with O(k) — a clear win when words are long.

Why the '#' delimiter? Without it, counts 12,0,0... and 1,20,0... would encode identically as "1200...". The delimiter makes each slot unambiguous.
Java Solution — O(n·k) Frequency Array
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> map = new HashMap<>();

        for (String word : strs) {
            // O(k) frequency count — no sorting needed
            int[] count = new int[26];
            for (char c : word.toCharArray())
                count[c - 'a']++;

            // encode int[26] → String key with '#' delimiter
            StringBuilder sb = new StringBuilder();
            for (int freq : count)
                sb.append(freq).append('#');
            String key = sb.toString();  // e.g. "1#0#0#0#1#...#1#..."

            map.computeIfAbsent(key, k -> new ArrayList<>()).add(word);
        }

        return new ArrayList<>(map.values());
    }
}

Key Insight
Every anagram has identical character frequencies. Encoding that as a string avoids O(k log k) sorting entirely.
"eat" → count[a]=1,count[e]=1,count[t]=1 → "1#0#0#0#1#...#1#..."
"tea" → count[a]=1,count[e]=1,count[t]=1 → "1#0#0#0#1#...#1#..." ← same key
