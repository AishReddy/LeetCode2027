128. Longest Consecutive Sequence

LeetCode Medium — HashSet + Sequence Start Detection

medium O(n) time
Problem

Given an unsorted array of integers nums, return the length of the longest consecutive sequence. You must write an O(n) algorithm.

nums = [100, 4, 200, 1, 3, 2]
Sequences: 1→2→3→4 (length 4), 100 (1), 200 (1)
Answer: 4
⚡ Sorting is O(n log n). The trick: put everything in a HashSet, then only start counting from a number that has no left neighbour (num-1 not in set) — that's a sequence start.
Core Idea — Sequence Start Detection
For every number, the question is: is this the start of a sequence?
set = {1, 2, 3, 4, 100, 200}

num=2: set.contains(1) → yes → skip (not a start)
num=1: set.contains(0) → no → start! count 1,2,3,4 → length=4
This ensures each sequence is counted exactly once from its leftmost element. Every element is visited at most twice across all sequences → O(n) total.
✓ The while loop inside looks O(n²) but isn't — each element is added to exactly one sequence, so the total inner iterations across all outer iterations is ≤ n.
Approach
1
Build HashSet: add all elements of nums into a HashSet for O(1) lookups.
2
For each num: check if num - 1 is in the set. If yes → skip (not a sequence start). If no → this is a sequence start.
3
Count the sequence: while num + length is in the set, keep incrementing length.
4
Update best: longest = Math.max(longest, length). Return longest.

Complexity Analysis
Time Complexity
O(n)
HashSet build = O(n). Each element is visited at most twice — once in outer loop, once in at most one inner while loop. Total = O(2n) = O(n).
Space Complexity
O(n)
HashSet stores all n elements.
Why not O(n²)? The while loop only runs for sequence starts. A number is only a sequence start once, and each element is counted in exactly one sequence. So total inner iterations ≤ n across all outer iterations.

Why not sort? Sorting is O(n log n) and requires the array to be modified. The HashSet approach is O(n) with no mutation.
Java Solution — Your Code
class Solution {
    public int longestConsecutive(int[] nums) {
        HashSet<Integer> set = new HashSet<>();
        for (int i : nums) {
            set.add(i);
        }
        int longest = 0;

        for (int i = 0; i < nums.length; i++) {
            int current = nums[i];   // moving pointer along the sequence
            int length  = 1;

            if (!set.contains(nums[i] - 1)) {    // sequence start gate
                while (set.contains(current + 1)) {
                    length++;
                    current++;
                }
                longest = Math.max(longest, length);
            }
        }
        return longest;
    }
}
Your version
Uses current pointer that moves forward
While: contains(current + 1)
Then: current++ and length++
Alternate version
Uses num + length as offset
While: contains(num + length)
Only length++, no extra variable
Pattern to remember
1. Build: HashSet<Integer> set — O(1) contains
2. Gate: if (!set.contains(nums[i] - 1)) → start only
3. Count: while (set.contains(current + 1)) { length++; current++; }
4. Track: longest = Math.max(longest, length)
Key Insight
The gate !set.contains(num - 1) is everything. It means: "don't count a sequence from the middle".

Without it, you'd recount sequences from every element — O(n²).
With it, you count each sequence exactly once from its leftmost element — O(n).
num=2: contains(1)? yes → skip
num=3: contains(2)? yes → skip
num=1: contains(0)? no → start! count → 4
