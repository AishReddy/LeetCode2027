Reverse String

Two-pointer in-place character swap

easy O(n) time O(1) space
Problem

Write a function that reverses a character array s in-place. You must do this by modifying the input array directly with O(1) extra memory.

Input:  ['h','e','l','l','o']
Output: ['o','l','l','e','h']

Input:  ['H','a','n','n','a','h']
Output: ['h','a','n','n','a','H']
⚡ Key insight: place one pointer at the start (l) and one at the end (r). Swap them and march inward. When they meet (or cross), the array is reversed.

✓ Only ⌊n/2⌋ swaps needed. The middle element (odd-length array) never moves — it's already in its mirror position.
Two-pointer approach
l
Left pointer (l) — starts at index 0, the first character. Advances inward (l++) after each swap.
r
Right pointer (r) — starts at s.length-1, the last character. Retreats inward (r--) after each swap.
↔
Swap & march — use a temp variable to swap s[l] ↔ s[r]. Repeat while l < r. When they meet or cross, done.
✓ No extra array. The classic 3-variable swap: temp = s[l]; s[l] = s[r]; s[r] = temp; — the same pattern used in sorting, partitioning, and every in-place rearrangement.

Java solution

        
class Solution {
    public void reverseString(char[] s) {
        int l = 0;
        int r = s.length - 1;

        while (l < r) {
            char temp = s[l];   // save left
            s[l] = s[r];          // overwrite left with right
            s[r] = temp;          // restore right from saved
            l++;
            r--;
        }
    }
}


        

            

                
Why l < r not l <= r?

                

                    When l == r both pointers are at the same middle element — swapping it with itself is useless. l < r stops one step earlier, saving one redundant swap.
                

            

            

                
Why a temp variable?

                

                    Without saving s[l] first, writing s[l] = s[r] destroys its value before you can copy it to s[r]. The 3-variable swap is the fundamental pattern.
                

            

            

                
Invariant

                

                    After each iteration: s[0..l-1] and s[r+1..n-1] are in their final reversed positions. The region [l..r] still needs processing. Loop terminates when that region is empty.
                

            

        

    


    
    

        
Complexity

        

            

                
Time

                
O(n)

                
Each element is touched exactly once. ⌊n/2⌋ swaps total — half the array.

            

            

                
Space

                
O(1)

                
Only three variables: l, r, temp. No extra array, no recursion stack.

            

        

        

            Two pointers meeting in the middle is the most elegant reversal. Some alternatives: XOR swap (no temp, but less readable), or using a stack (O(n) space — defeats the purpose).
