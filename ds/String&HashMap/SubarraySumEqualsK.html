560. Subarray Sum Equals K

LeetCode Medium — Prefix Sum + HashMap

medium O(n) time
Problem

Given an integer array nums and an integer k, return the total number of contiguous subarrays whose sum equals k.

⚡ Brute force is O(n²) — check every pair (i,j). The prefix sum trick reduces it to O(n) by asking: "how many earlier prefix sums equal prefixSum - k?"
Core Idea — Prefix Sum
Define prefixSum[i] = sum of nums[0..i]. The sum of subarray [j+1..i] is:
prefixSum[i] − prefixSum[j] = k
Rearranging:
prefixSum[j] = prefixSum[i] − k
So at each index i, we ask: how many times has prefixSum − k appeared before? Each occurrence is a valid subarray ending at i.
✓ Store prefix sum frequencies in a HashMap. Initialise with {0: 1} to handle subarrays starting from index 0.
Approach
1
Initialise: prefixSum = 0, count = 0, map = {0: 1}. The seed 0→1 handles subarrays that start at index 0.
2
For each element: add it to prefixSum.
3
Check the map: if prefixSum − k exists in the map, add its frequency to count. Each stored occurrence represents a valid subarray ending here.
4
Update map: increment map[prefixSum] by 1. Then move to the next element.

Why Initialise Map with {0 → 1}?
Consider nums=[3], k=3. At index 0, prefixSum=3, so we look for prefixSum−k = 0 in the map.

Without the seed: 0 is not in map → count stays 0 → wrong answer.
With the seed {0:1}: found → count += 1 → correct.

The seed represents the empty prefix — a subarray that starts at index 0 needs a "zero sum before it" to exist.
Complexity Analysis
Time Complexity
O(n)
Single pass through the array. HashMap get/put is O(1) average.
Space Complexity
O(n)
HashMap stores at most n+1 distinct prefix sums.
Works with negatives: Unlike the sliding window approach, this works even when nums contains negative numbers — because we're not shrinking a window, just counting prefix sums.

Sliding window won't work here — it only works when all numbers are positive (so extending always increases sum). With negatives, you can't predict whether to shrink or expand.
Java Solution
class Solution {
    public int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> map = new HashMap<>();
        map.put(0, 1);          // seed: empty prefix

        int prefixSum = 0;
        int count     = 0;

        for (int num : nums) {
            prefixSum += num;

            // how many earlier prefixes give a valid subarray ending here?
            if (map.containsKey(prefixSum - k))
                count += map.get(prefixSum - k);

            // record this prefix sum
            if (map.containsKey(prefixSum))
                map.put(prefixSum, map.get(prefixSum) + 1);
            else
                map.put(prefixSum, 1);
        }

        return count;
    }
}
Pattern to remember
1. Seed: map.put(0, 1) before the loop
2. Query: if (map.containsKey(prefixSum - k)) count += map.get(prefixSum - k)
3. Update: containsKey → put(ps, get+1) else put(ps, 1) — after query
Key Insight
You never look at pairs of indices explicitly. Instead you ask at every index:
"Has prefixSum − k appeared before?"
If yes — each past occurrence marks the start of a valid subarray ending here.

Order matters: always query the map before updating it, otherwise a subarray of length 0 (same index) could be counted.
