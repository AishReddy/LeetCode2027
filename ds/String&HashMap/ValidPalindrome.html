Two Pointers

Valid Palindrome

Converging two-pointer character comparison

easy O(n) time O(1) space
Problem

Given a string str, determine if it is a palindrome — a string that reads the same forwards and backwards.

"racecar" → true  // r·a·c·e·c·a·r mirrors perfectly
"madam"   → true  // m·a·d·a·m mirrors perfectly
"hello"   → false  // h≠o at positions 0 and 4
"a"       → true  // single char, l never < r
⚡ Key insight: a palindrome is symmetric around its center. Check symmetry by pointing one pointer at each end and converging — if every pair matches, it's a palindrome.

Two-pointer approach
l
Left pointer (l) — starts at index 0. Advances inward (l++) after each matching pair. Represents the "front" of the string.
r
Right pointer (r) — starts at str.length()-1. Retreats inward (r--) after matching. Represents the "back" of the string.
?
Compare & decide — if charAt(l) != charAt(r), return false immediately. If they match, advance both. If l ≥ r without mismatch, return true.
✓ Early exit on first mismatch — no need to check the rest. Best case O(1) (first chars differ), worst case O(n/2) comparisons.

Java solution

        
public boolean isPalindrome(String str) {
    int l = 0;
    int r = str.length() - 1;

    while (l < r) {
        if (str.charAt(l) != str.charAt(r)) {
            return false;          // mismatch → not palindrome
        }
        l++;
        r--;
    }
    return true;               // all pairs matched
}


        

            

                
Why l < r?

                

                    When l == r, both pointers are on the same middle character — comparing it to itself is always true and redundant. l < r skips it cleanly.
                

            

            

                
vs. Reverse String (344)

                

                    Same converging pointer pattern, but instead of swapping, we compare. No temp needed. A mismatch proves it's not a palindrome instantly.
                

            

            

                
Invariant

                

                    After each iteration: all character pairs s[0..l-1] ↔ s[r+1..n-1] have been verified to match. The region [l..r] is still unverified. Exits when region is empty → all pairs matched.
                

            

        

    


    
    

        
Complexity

        

            

                
Time

                
O(n)

                
At most ⌊n/2⌋ comparisons. Early exit on first mismatch means average case is much faster for non-palindromes.

            

            

                
Space

                
O(1)

                
Only two integer pointers. No copy of the string, no stack, no extra data structure.

            

        

        

            Common wrong approach: reverse the string and compare — also O(n) time but O(n) extra space for the copy. This two-pointer approach avoids that entirely.
