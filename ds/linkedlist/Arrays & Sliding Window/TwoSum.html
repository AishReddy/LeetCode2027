Easy Array Hash Map LeetCode #1

Two Sum / Java

Given an array of integers and a target, return the indices of the two numbers that add up to the target.

Problem Statement

Given an array nums and an integer target, return indices [i, j] such that nums[i] + nums[j] == target and i != j. Exactly one valid answer always exists.

Example 1
Input: [2, 7, 11, 15], target = 9
Output: [0, 1]
Because nums[0] + nums[1] = 2 + 7 = 9
Example 2
Input: [3, 2, 4], target = 6
Output: [1, 2]
Because nums[1] + nums[2] = 2 + 4 = 6
Approaches

Brute Force

Check every pair of elements using nested loops. For each element, scan all elements after it to find a matching complement.

Time O(n²) Space O(1)

Hash Map (One Pass)

Store each seen value and its index in a HashMap. For each element, check if its complement already exists — O(1) lookup.

Time O(n) Space O(n)
Solution Code
TwoSum.java 
import java.util.HashMap;
import java.util.Map;

class Solution {

    /**
     * Returns indices of two numbers that add up to target.
     * Time  : O(n)  — single pass through the array
     * Space : O(n)  — HashMap stores at most n entries
     */
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int comp = target - nums[i];

            if (seen.containsKey(comp)) {
                return new int[]{seen.get(comp), i};
            }

            seen.put(nums[i], i);
        }

        throw new IllegalArgumentException("No valid pair found");
    }
}
How It Works
1

Create a HashMap

Initialise seen as a Map<Integer, Integer> mapping each value to its index. This gives O(1) average lookup time.

2

Iterate once through the array

For every element at index i, compute its complement: comp = target - nums[i]. This is the value we need to have seen earlier.

3

Check the map — O(1) lookup

Call seen.containsKey(comp). If true, the complement was encountered in a previous iteration and its index is stored in the map.

4

Return immediately on match

Return [seen.get(comp), i] — the index of the complement and the current index. We never need to look further.

5

Otherwise, record current element

Store seen.put(nums[i], i) so future iterations can find this element as a complement. We store after the check to avoid using the same index twice.

Time & Space Complexity
Metric
Value
Explanation
Time — Best
O(1)

The very first element's complement is already in the map (empty in practice — but if the answer is at index 0,1 the loop exits immediately).

Time — Average
O(n)

We traverse the array once. Each containsKey and put is O(1) amortised due to HashMap's hash-based bucketing.

Time — Worst
O(n)

Answer is at the last pair, so we scan all n elements. Still linear — not affected by sorting or nesting.

Space
O(n)

The HashMap can hold at most n−1 entries before a match is found. In the worst case (answer at last pair) nearly all elements are stored.

vs Brute Force
O(n²)

Nested loops check every pair. For n = 10,000 that's ~50 million comparisons vs ~10,000 with the hash map approach.

Edge Cases

Duplicate values

The same number appears twice and both are needed. Storing after the check ensures the same index isn't reused.

Input: [3, 3], target = 6 → [0, 1]

Negative numbers

Works naturally — HashMap keys can be any integer, and target - nums[i] handles negatives correctly.

Input: [-3, 4, 7], target = 4 → [0, 2]

Answer at end

Worst case for runtime — the matching pair is the last two elements. Still O(n), just processes the full array.

Input: [1, 2, 3, 4], target = 7 → [2, 3]

Zero values

Zeros are valid keys in a HashMap. target - 0 = target, so the algorithm searches for target itself.

Input: [0, 4, 0], target = 0 → [0, 2]
