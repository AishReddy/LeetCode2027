141. Linked List Cycle

LeetCode Easy — Floyd's Tortoise & Hare

easy O(n) time  |  O(1) space
Problem

Given the head of a linked list, determine if it has a cycle — return true if there is a cycle, false otherwise.

3 → 2 → 0 → -4 ↩ (back to 2) ← cycle exists → true
1 → 2 → null                ← no cycle → false
⚡ A HashSet approach is O(n) time but O(n) space. Floyd's two-pointer (slow/fast) detects a cycle in O(n) time and O(1) space — no extra memory.
Why Floyd's Algorithm Works
slow moves 1 step per iteration. fast moves 2 steps per iteration.

No cycle: fast reaches null → return false.
Cycle exists: both pointers enter the cycle. fast gains 1 step on slow each iteration. Eventually fast laps slow and they meet.

✓ If there's a cycle, fast and slow will always meet — fast can never "skip over" slow inside a cycle because it only gains 1 step per iteration.
Approach — Floyd's Tortoise & Hare
1
Initialise: slow = head, fast = head.
2
Move: while fast != null && fast.next != null:
slow = slow.next (1 step)
fast = fast.next.next (2 steps)
3
Meet: if slow == fast → cycle detected → return true.
4
No cycle: loop exits because fast hit null → return false.
Walkthrough   3 → 2 → 0 → -4 → (back to 2)
Nodes: idx 0=3, 1=2, 2=0, 3=-4   Cycle: -4.next → node[1] (val=2)
↩ -4.next points back to 2 (cycle)
step slow fast slow==fast?
Complexity Analysis
Time Complexity
O(n)
No cycle: fast reaches null in n/2 steps. Cycle: fast catches slow within one full loop of the cycle — O(n) total.
Space Complexity
O(1)
Only two pointers — slow and fast. No HashSet, no visited array.
HashSet alternative: store each visited node in a Set — O(n) space. Floyd's eliminates that at the cost of being slightly harder to reason about.

Why fast.next != null? fast.next.next would throw NullPointerException if fast.next is null. Both checks are needed.
Java Solution
public class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;

        while (fast != null && fast.next != null) {
            slow = slow.next;          // 1 step
            fast = fast.next.next;     // 2 steps

            if (slow == fast) return true;   // met → cycle!
        }

        return false;   // fast hit null → no cycle
    }
}
3 things to remember
1. Condition: fast != null && fast.next != null — both needed
2. Move: slow = slow.next   fast = fast.next.next
3. Meet: if (slow == fast) return true — reference equality, not value
Key Insight
Think of a circular track. The hare (fast) runs at 2x speed. The tortoise (slow) runs at 1x. If there's a loop, the hare will eventually lap the tortoise — they must meet.

Note: slow == fast compares references (same node object), not values. Two nodes with the same value but different positions would not be equal.
