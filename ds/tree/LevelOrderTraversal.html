Binary Tree Level Order Traversal

BFS with a queue — process one level at a time

medium O(n) time O(n) space
Problem

Given the root of a binary tree, return the level order traversal of its nodes' values — left to right, level by level — as a List<List<Integer>>.

Tree:
     3
    / \
   9  20
       / \
     15  7

Output: [[3], [9,20], [15,7]]
⚡ Key insight: BFS naturally visits nodes level by level. The trick is knowing where one level ends and the next begins — snapshot the queue size at the start of each level, then process exactly that many nodes.
BFS with level-size snapshot
1
Seed the queue — enqueue root. Each iteration of the outer loop processes one complete level.
2
Snapshot the level size — int size = queue.size() before the inner loop. This captures exactly how many nodes are on the current level, even as we enqueue children.
3
Process & enqueue children — dequeue size nodes, add their values to the current level list, enqueue non-null left and right children. Add completed list to result.
✓ The inner for (int i = 0; i < size; i++) loop is the key. It processes exactly one level. Children enqueued during this loop form the next level — they're counted in the next iteration's size snapshot.

Full Java solution
class Solution {
    public List<List<Integer>> levelOrder(TreeNode root) {
        List<List<Integer>> result = new ArrayList<>();
        if (root == null) return result;

        Queue<TreeNode> q = new LinkedList<>();
        q.offer(root);

        while (!q.isEmpty()) {
            int size = q.size();                     // nodes on this level
            List<Integer> level = new ArrayList<>();

            for (int i = 0; i < size; i++) {
                TreeNode node = q.poll();
                level.add(node.val);
                if (node.left  != null) q.offer(node.left);
                if (node.right != null) q.offer(node.right);
            }
            result.add(level);
        }
        return result;
    }
}
Why snapshot size?
As you dequeue nodes and enqueue their children, q.size() changes mid-loop. Snapshotting it before the inner loop freezes the count for this level — without it, you'd process part of the next level too.
Why null check before enqueue?
Never enqueue null. If you do, you'll dequeue null and get a NullPointerException on null.left. Always check != null before q.offer().
DFS vs BFS for level order
DFS (recursion) can also do level order by passing the depth as a parameter and appending to result.get(depth). But BFS is more natural — the queue literally holds "the next level" at all times. DFS uses O(h) call stack space; BFS uses O(w) queue space (w = max width).
Complexity
Time
O(n)
Every node is enqueued and dequeued exactly once. Each operation is O(1). Total = O(n).
Space
O(n)
Queue holds at most one full level at a time. Widest level of a perfect binary tree = n/2 nodes → O(n). Output list also O(n).
The queue acts as a FIFO buffer between levels. When processing level k, the queue contains exactly the nodes of level k+1 after the inner loop finishes — ready for the next iteration.
