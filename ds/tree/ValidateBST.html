Validate Binary Search Tree

DFS with min/max bounds — pass constraints down the tree

medium O(n) time O(h) space
Problem

Given the root of a binary tree, determine if it is a valid Binary Search Tree (BST). A valid BST satisfies:

1. The left subtree of a node contains only nodes with keys strictly less than the node's key.
2. The right subtree contains only nodes with keys strictly greater than the node's key.
3. Both left and right subtrees must also be valid BSTs.
⚠️ Tricky case: checking only parent–child pairs is NOT enough. Node 6 in a right subtree of 5 must be > 5, but if 5's ancestor is 10, then 6 must also be < 10. You must carry bounds down the tree.
The classic mistake — local vs global bounds
✗ Wrong — local check only
Each node only checks its direct parent.

root.left.val < root.val
root.right.val > root.val

Misses cases where a node violates an ancestor's bound. The tree below looks locally valid but is NOT a BST:

  5
 / \
1  4
   / \
  3  6
4 < 5 ✓ locally, but 4 is right child of 5, so must be > 5 ✗
✓ Correct — pass bounds down
Each node carries a [min, max] window of valid values, inherited from ancestors.

Going left: update max → node.val
Going right: update min → node.val

Every node must satisfy: min < node.val < max

Bounds start as [-∞, +∞] and tighten as we descend. Any violation → immediately return false.
Algorithm — recursive DFS with bounds
1
Base case — if root == null, return true. An empty subtree is always a valid BST.
2
Check bounds — if node.val ≤ min or node.val ≥ max, return false. The current node violates an ancestor's constraint.
3
Recurse with tightened bounds — left child gets [min, node.val]; right child gets [node.val, max]. Both must return true.
✓ Use Long.MIN_VALUE / Long.MAX_VALUE as initial bounds to handle edge cases where node values equal Integer.MIN_VALUE or Integer.MAX_VALUE.

Full Java solution
class Solution {
    public boolean isValidBST(TreeNode root) {
        return validate(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }

    private boolean validate(TreeNode node, long min, long max) {
        if (node == null) return true;         // null = valid

        if (node.val <= min || node.val >= max)  // bounds violated
            return false;

        return validate(node.left,  min, node.val)  // left: max = node.val
            && validate(node.right, node.val, max); // right: min = node.val
    }
}
Why Long instead of Integer?
If a node's value is Integer.MIN_VALUE, we need a bound smaller than it. Long.MIN_VALUE guarantees that. Same for Integer.MAX_VALUE on the upper bound.
Why strict < and >?
BST definition requires strictly less/greater — no duplicate values allowed. So the check is val <= min || val >= max (fail if equal to bound).
In-order traversal alternative
A valid BST's in-order traversal is strictly increasing. Traverse in-order, track the previous value — if curr <= prev, return false. Same O(n)/O(h), different style.
Short-circuit evaluation
The && in the return statement short-circuits: if the left subtree is invalid, the right subtree is never checked — saving time in practice.
Complexity
Time
O(n)
Each node is visited at most once. Short-circuit on invalid tree means often faster in practice.
Space
O(h)
Call stack depth = tree height h. Balanced: O(log n). Skewed worst case: O(n).
